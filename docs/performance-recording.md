# Performance recording

Use **Record** beside **Mixer** to record an ordinary audio Clip from the current playhead. The button changes to **Recording** with a stop icon during preparation, count-in and capture; the countdown appears inside that same button. Click it again to stop. The transport Stop button or Space also stops capture. Recording requires an editing draft, microphone access, browser audio and the configured media store.

The settings button in the upper-right header selects the microphone and count-in: none, four quarter-note clicks, or one bar of the current meter. Four clicks is the default. Use headphones; monitoring is off, and clicks are never digitally mixed into captured PCM or WAV exports. Accompaniment assets and the microphone must be ready before count-in begins. Music onset and capture frames share the studio AudioContext. Hardware input/output latency is not automatically calibrated; acoustic alignment still needs a microphone/headphone rehearsal and can be adjusted with normal Clip movement.

Stopping a nonempty recording automatically uploads its WAV and applies one typed source/part/track/Clip batch at the captured playhead. The new track is unmuted. Re-recording adds another independent track; earlier audio, mute and solo states remain unchanged. Use normal playback, mute/solo, trimming, splitting, moving, deleting and library reuse. There is no dedicated A/B or take-selection interface. Undo is beside the arrangement's split/copy/delete actions. Explicit Save or Save as still controls the saved project.

An interrupted recording retains received frames. Cancelling before onset creates no empty Clip. Hiding the page, device loss, cancellation or project changes stop capture and accompaniment. Pending PCM, uploads and placement participate in departure protection. Failed placement keeps WAV/PCM in page memory: use Retry or Download WAV from the toast or recording settings. Retry reuses the same command receipt; it cannot duplicate an accepted recording after a lost acknowledgement. A version conflict does not silently move the captured origin or rebase the recording: download it before leaving and import it into the intended draft. Discard releases local recovery audio. Recovery PCM does not survive confirmed departure, refresh or browser termination.

Producer uses `control_studio` for metronome, playback and stop, and the separate `record_audio` tool for humming or singing. The recording tool requires the agreed phrase, Clip name, explicit named new track or existing audio track, start/end quarter-note beats, count-in, accompaniment and follow-up choice (`keep_audio` or `transcribe_notes`). Missing phrase/destination/range choices are resolved in conversation; a referenced selected Clip or named section can supply a known range. Once resolved, recording starts without a Record click. Microphone permission still belongs to the browser. Dry humming disables accompaniment and ongoing metronome clicks. The capture worklet stops at the selected end frame; early cancellation retains only received audio.

Requests belong to the initiating page instance and accepted project version. The browser claims each request once and acknowledges readiness or failure; reloads and history do not execute old controls. Existing audio-track targets are validated for ownership and locks, and ordinary typed placement performs the same checks again. A successful preparation result means prepared, not recorded or placed. Text-triggered recording starts after that run completes. Voice-triggered recording also waits for the final spoken response and every queued local audio chunk to finish. Interrupting the preparation reply cancels the pending plan. Preparation cannot mix staged content edits into the same run.

After capture, the owning browser reports its lifecycle and placement result. The server verifies the actual receipt, source, Clip, target/range and owned media before constructing a fresh musical context. The existing realtime conversation can continue from that result without a new greeting; text conversation starts an idempotent application follow-up. Neither path fabricates a user transcript or requires the user to select/upload the recording again. Humming, rhythmic ideas and real vocal capture default to keeping audio; only an explicit request for notation/editable notes selects transcription. Requested audio-to-notes processing reuses the existing local analysis tool and preserves the original recording; partial recordings require a further user decision. Note conversion remains limited to 30 seconds and creates a muted editable note track for review. Recognition quality remains dependent on the actual recorded signal.

`save_project` and `export_audio` reuse the normal browser Save/Save as and WAV export paths. Save as requires a name; file tools wait for real completion and cannot mix with staged musical edits. Concurrent file-control requests are serialized, so an export after Save uses the newly accepted version. Explicit Save remains necessary to update a saved base project.

During count-in/capture, conversation audio uplink and Producer speech are held. Ending capture restores the existing voice session without another greeting or call tone. The selected StepFun voice and default server VAD settings remain unchanged. The older lyric-guided vocal reference workflow remains available separately.

Software verification covers required recording parameters, finite shared-clock capture, dry input, existing/new track placement, locks, interrupted audio, voice holds/draining, page ownership, duplicate events, fresh recording context, continuation, file-tool serialization, version conflicts and Undo. Browser verification uses synthetic input and the real Producer, including clarification before recording, automatic capture/stop/placement and automatic audio-to-notes follow-up. Real microphone latency and the complete spoken film rehearsal remain to be checked with the performer.
